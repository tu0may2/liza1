# Платформа продаж

Учёт работы с контрагентами: документы, заказы, оплаты с графиком, прайс-листы,
база документации и аналитика. Работает на вашем компьютере: программа на
Python поднимает локальный сервер, страница открывается в обычном браузере.
Наружу ничего не уходит.

## Что нужно для запуска

Только **Python 3** (версия 3.9 или новее). Больше ничего: ни баз данных, ни
библиотек, ни интернета.

**Windows.** Если Python ещё не стоит, скачайте его с
[python.org/downloads](https://www.python.org/downloads/) и при установке
обязательно отметьте галочку **«Add Python to PATH»**.

**macOS.** Python 3 обычно уже есть. Проверить: откройте Терминал и наберите
`python3 --version`. Если команды нет — поставьте с того же сайта.

## Как запустить

1. Распакуйте папку целиком (не запускайте из архива).
2. **Windows** — двойной щелчок по `start.cmd`.
   **macOS и Linux** — двойной щелчок по `start.command`.
3. Откроется чёрное окно с надписью «Платформа продаж запущена» и сам браузер.

Чёрное окно закрывать нельзя — пока оно открыто, платформа работает. Чтобы
закончить, нажмите в нём `Ctrl+C` или просто закройте его.

Если двойной щелчок не сработал, откройте Терминал (или командную строку) в
папке платформы и наберите:

```bash
python3 server.py
```

### macOS: «Файл не был открыт»

При первом запуске macOS может показать окно с жёлтым треугольником: «Apple не
удалось подтвердить, что файл не содержит вредоносного ПО». Так система
встречает **любой** скачанный скрипт без платной подписи разработчика Apple —
содержимое она не проверяла, просто не знает автора.

**Нажмите «Готово». Кнопку «Переместить в Корзину» не нажимайте** — она удалит
платформу.

Чтобы снять запрет раз и навсегда, откройте Терминал (Cmd + Пробел →
«Терминал»), наберите команду ниже, **не нажимая Enter** — в конце нужен
пробел:

```bash
xattr -dr com.apple.quarantine 
```

затем перетащите мышью папку с платформой прямо в окно Терминала — путь
подставится сам — и нажмите Enter. После этого двойной щелчок по
`start.command` работает как обычно.

Можно и без Терминала: **Системные настройки → Конфиденциальность и
безопасность**, пролистать вниз до строки про `start.command` и нажать
«Открыть всё равно».

А если возиться не хочется, платформу всегда можно запустить так: в Терминале
набрать `python3 ` (с пробелом в конце), перетащить туда файл `server.py` и
нажать Enter. Этот способ ничего не меняет в системе, но повторять его нужно
при каждом запуске.

Те же указания лежат в архиве файлом «ЕСЛИ MAC НЕ ЗАПУСКАЕТ.txt».

Адрес платформы — `http://127.0.0.1:8765`. Его можно открыть в любом браузере,
пока программа запущена, и добавить в закладки.

> Адрес начинается с `127.0.0.1` — это ваш собственный компьютер. Из сети к
> платформе не подключиться: сервер принимает только местные обращения.

### С телефона в той же сети

По умолчанию платформа доступна только с этого компьютера. Если нужно открывать
её с телефона по домашнему Wi-Fi, запустите так:

```bash
python3 server.py --host 0.0.0.0
```

и заходите с телефона по адресу `http://<адрес компьютера>:8765`. Делайте это
только в доверенной сети: пароля у платформы нет, и любой в той же сети сможет
открыть ваши данные.

## Где лежат данные

Всё хранится в папке `data` рядом с программой:

```
data/platforma.db   записи и история правок
data/files/         вложенные файлы как есть
```

**Резервная копия — это копия папки `data`.** Скопируйте её на флешку или в
облако, и у вас есть всё: и записи, и документы. Чтобы переехать на другой
компьютер, перенесите туда папку платформы вместе с `data`.

Во вкладке **Данные** есть ещё выгрузка записей в JSON — она маленькая и
годится как частый снимок состояния или для переноса справочников. Сами файлы
в неё не входят: копировать папку быстрее и надёжнее.

## Что внутри

**Обзор** — что происходит сейчас: поступления за месяц в сравнении с прошлым,
что ждём по графику, что просрочено, долг по счетам, заказы в работе. Ниже —
кольца расчётов, нал и безнал по месяцам, ближайшие платежи и доли контрагентов.

**Вкладка контрагента** (Амур, Сахалинские акулы и каждый, кого вы добавите) —
отдельная вкладка в верхнем ряду, внутри девять разделов:

* *Сводка* — выставлено, оплачено, долг или аванс, просрочка, заказы в работе,
  расчёты по каждому договору отдельно.
* *Документы* — история: договор, спецификация, счёт, оплата, УПД, акт.
* *Заказы* — заказы контрагента со статусом и готовностью оплаты.
* *Оплаты* — поступления, доли нала и безнала, график по месяцам.
* *График* — плановые платежи со сроками и подсветкой просрочки.
* *Прайс-лист* — цены этого контрагента: файлом и позициями.
* *Документация* — все файлы контрагента в одном месте, с поиском.
* *Договоры* — справочник договоров с расчётами по каждому.
* *Реквизиты* — карточка организации.

**Заказы** — список всех заказов и создание нового. Заказ заводится пустым
черновиком и дополняется постепенно; из его карточки выписывается счёт или
спецификация, ставится платёж в график, отмечается оплата.

**Оплаты** — график платежей, план против факта, разрезы по договорам и по
способу оплаты, таблица всех поступлений.

**Документы** — вся документация по всем контрагентам в одной таблице.

**Аналитика** — цепочка «заказ → счета → оплаты», итоги по контрагентам,
поступления по месяцам, суммы заказов, топ позиций.

**Контрагенты** — список и добавление новых.

**История** — что и когда менялось, с возможностью вернуть любое состояние.

**Данные** — выгрузка, загрузка, печать, очистка.

## Файлы: PDF, Word, Excel, сканы и скриншоты

Приложить файл можно почти везде:

| Куда | Как |
|---|---|
| К контрагенту | вкладка контрагента → **Документация** |
| К договору | вкладка **Договоры** → кнопка **Файлы** в строке |
| К документу (счёт, спецификация, УПД, акт) | таблица документов → кнопка **Файлы** |
| К заказу | карточка заказа → блок **Файлы заказа** |
| К оплате | таблица оплат → кнопка **Файлы** |
| К прайс-листу | вкладка контрагента → **Прайс-лист** |

Принимаются PDF, Word (`doc`, `docx`), Excel (`xls`, `xlsx`, `csv`), картинки
и скриншоты (`png`, `jpg`, `heic` и другие), текст, архивы и письма — до 200 МБ
каждый. Файлы перетаскиваются мышью прямо в рамку или выбираются обычным
диалогом, по нескольку за раз.

Файл открывается нажатием на имя — браузер покажет PDF или картинку прямо во
вкладке, остальное предложит скачать. Кнопка **Скачать** сохраняет файл с его
исходным именем, в том числе кириллическим.

У файлов договоров и документов есть отметка подписания: *не подписан*,
*подписан одной стороной*, *подписан с обеих сторон*. Поэтому к одному счёту
спокойно лежат оба экземпляра — отправленный и вернувшийся подписанным. В
таблице у документа видна скрепка со сводкой, а фильтр **Скан** отбирает
документы по этому признаку.

## База документации по контрагенту

Раздел **Документация** в карточке контрагента собирает все его файлы в одном
месте: сканы документов, прайсы, вложения заказов, договоров и оплат, плюс то,
что положили прямо сюда — переписку, доверенности, фотографии.

Рядом с каждым файлом написано, откуда он: «Счёт №114», «Заказ 118», «Договор
Основной». Сверху — фильтр по разделу и поиск по имени файла, а также сколько
всего файлов и сколько места они занимают.

## История правок

Перед каждой правкой сервер сохраняет предыдущее состояние базы. Во вкладке
**История** видно, что и когда менялось: «Добавлена оплата 500 000 ₽ — Амур»,
«Изменён заказ 124», «Загружен файл «Договор.pdf» — Амур · Договор Основной».

Любую строку со снимком можно вернуть кнопкой **«Вернуть это состояние»**.
Текущее состояние при этом тоже попадёт в историю, так что откат можно
отменить. Загрузки файлов в истории видны, но возврату не подлежат — файл
остаётся на диске, пока его не удалят вручную.

Хранится 500 последних снимков.

## Как устроен учёт

**Контрагент** → у него один или несколько **договоров** (основной, бартерный,
любой другой). К договору привязываются **заказы**, **документы** и **оплаты**.

**Долг** считается как сумма выставленных счетов минус поступившие оплаты.
Договоры и спецификации в долг не входят: требование создаёт счёт. Если
оплачено больше выставленного, вместо долга показывается аванс.

**График платежей** живёт отдельно от фактических оплат. Строка графика — это
план; пока не нажата кнопка «Оплачено», она не попадает ни в одну сумму
поступлений.

**Статусы заказа**: черновик → согласован → в документах → отгружен → закрыт.

### Заказ, его документы и оплаты частями

Заказ — один, сколько бы документов и платежей к нему ни относилось:

* **сумма заказа** считается по его позициям;
* **выставлено** — только по счетам. Спецификация и УПД описывают ту же
  поставку и в сумму не идут: если сложить все документы подряд, заказ вырастет
  втрое;
* **оплачено** — по платежам этого заказа, сколько бы их ни было;
* **остаток** — сумма заказа минус оплаченное.

У оплаты можно указать счёт, по которому она пришла. В строке счёта видно,
сколько по нему уже поступило и сколько осталось. В аналитике есть таблица
«Заказ → счета → оплаты»: одна строка на заказ, с пометками, какие документы
выпущены, и отметкой, если пришло больше, чем выставлено.

## Прайс-лист контрагента

У каждой компании цены свои, поэтому прайс живёт в её вкладке.

**Файлом** — присланный PDF, Excel или фото, на который ссылаются в переписке;
версий можно хранить сколько угодно.

**Позициями** — артикул, название, единица, цена, комментарий. Из них собирается
заказ: в карточке заказа есть кнопка **«Из прайса»**, она открывает список
позиций, где отмечаются нужные и ставится количество. Цена подставится, но в
заказе её можно поправить — договорная скидка не правит сам прайс.

## Первые шаги с чистой базы

1. Вкладка **Данные** → «Очистить всё и начать с нуля».
2. **Контрагенты** → «+ Новый контрагент». Откроется его вкладка на договорах.
3. Заведите договоры — столько, сколько есть на самом деле.
4. **Прайс-лист**: положите присланный файл и занесите позиции.
5. **+ Новый заказ**: наберите позиции кнопкой «Из прайса».
6. Согласовали — «Выписать счёт» и «Внести в график оплат» из карточки заказа.
7. Деньги пришли — в графике нажмите «Оплачено».
8. Пришёл подписанный экземпляр — «Файлы» у документа, отметка «Подписан с
   обеих сторон».

## Файлы программы

```
server.py               сервер: хранение, история, файлы
start.cmd               запуск в Windows
start.command           запуск в macOS и Linux
ЕСЛИ MAC НЕ ЗАПУСКАЕТ.txt   что делать с предупреждением macOS
index.html              страница платформы
static/css/app.css      оформление, тёмная и светлая темы
static/fonts/           Oranienbaum и Jost, вшиты в папку
static/js/format.js     рубли, даты, склонения
static/js/files.js      работа с вложениями
static/js/store.js      модель данных и обмен с сервером
static/js/charts.js     графики и кольца (собственный SVG)
static/js/app.js        экраны, формы, расчёты
data/                   ваши данные (появится при первом запуске)
```

Внешних зависимостей нет ни одной: ни сервер, ни страница ничего не загружают
из интернета, включая шрифты. Платформа одинаково работает и без сети.

## Если что-то пошло не так

**«Нет связи с программой»** на странице — закрыли чёрное окно. Запустите
`start.cmd` (или `start.command`) заново и обновите страницу.

**Порт занят** — платформа сама возьмёт следующий свободный и напишет об этом в
окне. Можно задать порт вручную: `python3 server.py --port 8010`.

**Не открывается браузер** — откройте его сами и наберите адрес из чёрного окна.

**macOS не даёт запустить** — см. раздел «macOS: „Файл не был открыт“» выше.

**Пропали данные** — проверьте, что рядом с `server.py` лежит папка `data`.
Запуск из другой папки создаст пустую базу: платформа всегда берёт данные
оттуда, где лежит сама.

## Оформление

**Палитра.** Основной цвет синий: на шкале `#0A1B2E … #F2F6FB` держатся
поверхности, текст и действия. Зелёная шкала `#051F20 … #DAF1DE` и малиновый
`#C50337` с бордо `#6B1E23` работают на акцентах: состояния, метки договоров и
способов оплаты, цвета серий на графиках.

**Шрифты.** Заголовки и крупные числа — Oranienbaum, остальной текст — Jost.
Оба лежат в `static/fonts/` и не загружаются из сети.

**Темы.** Тёмная по умолчанию, светлая — снежинкой в правом верхнем углу; выбор
запоминается.

**Котик** выглядывает оттуда, где пока пусто: из блоков без данных, из зон
загрузки файлов и из-за нижнего края страницы.

**Цвета графиков.** Частые пары — основной и бартерный договор, безнал и нал —
показаны шалфейным и малиновым; пара проверена скриптом доступности и
расходится при протанопии и дейтеранопии с запасом. Там, где категорий больше
двух, цвет берётся ступенями светлоты одного тона: четыре разных тона из зелени
и красного дали бы красно-зелёное смешение, а ступени светлоты различимы при
любой форме дальтонизма. У каждого графика есть кнопка «Таблицей».

На столбчатых диаграммах подсвечен последний период, в котором что-то было.
Подсветка — только акцент: высота столбцов и подписи значений не меняются,
график читается и без неё.
